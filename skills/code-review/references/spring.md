# Java/Spring 리뷰 체크리스트

`code-review` 절차에 얹어서 사용한다. 여기 있는 항목은 실제로 장애로 이어진 적이 있는 것들만 둔다.

## 트랜잭션
- `@Transactional`이 Service 유스케이스 메서드에 있는가 (Controller/Repository에 붙지 않았는가)
- 트랜잭션 안에서 외부 호출(HTTP, 메시지 발행, 메일, 결제)을 하는가 → Blocking 후보
- 같은 클래스 내부 호출로 `@Transactional`이 무력화되지 않는가
- 조회 전용 경로에 `readOnly = true`가 빠져 있지 않은가
- 롤백 대상 예외가 의도와 일치하는가 (checked exception 기본 미롤백)

## JPA / 영속성
- 반복 조회로 N+1이 발생하는가 (연관 필드를 루프 안에서 접근)
- `FetchType.EAGER`가 새로 추가되었는가
- 영속성 컨텍스트 밖에서 지연 로딩 필드에 접근하는가
- entity가 Controller 응답으로 그대로 나가는가
- 양방향 연관에서 한쪽만 갱신해 정합성이 깨지는가
- `save()` 없이 변경 감지에 의존하는 코드가 트랜잭션 밖에 있는가

## 동시성
- 조회 후 갱신(read-modify-write) 구간이 락 없이 열려 있는가
- 싱글턴 빈에 가변 필드가 생겼는가
- `@Async` / 스레드풀 작업이 트랜잭션·보안 컨텍스트를 기대하고 있는가

## 웹 계층
- 요청 DTO에 검증 애노테이션이 있고 `@Valid`가 실제로 걸려 있는가
- 예외 → HTTP 상태 매핑이 한 곳(`@RestControllerAdvice`)에 모여 있는가
- 에러 응답 형식이 기존과 일치하는가
- 페이징 파라미터에 상한이 있는가 (size 무제한 요청 방어)

## 설정 / 보안
- 비밀값이 코드나 property 파일에 하드코딩되었는가 → Blocking
- 새 property가 profile별로 정의되어 있는가, 없을 때 기본값이 안전한가
- 인증 없이 열린 엔드포인트가 추가되었는가
- 로그에 토큰·비밀번호·개인정보가 찍히는가

## 테스트
- 트랜잭션 롤백에 의존해 통과하지만 실제 커밋 경로는 검증하지 않는 테스트인가
- 시간·랜덤·외부 호출이 고정되지 않아 간헐적으로 깨질 여지가 있는가
- Mock 검증만 있고 결과 상태 검증이 없는가
